# 站点使用说明

本文档面向仓库维护者与投稿者，说明本仓库（VitePress 静态站点）的本地开发、内容投稿与部署流程。

## 一、项目结构

- 内容文件保持在仓库根目录原位，不搬家：
  - `队伍线/<队伍名>/main.md` —— 队伍条目
  - `个人线/<选手名>/main.md` —— 选手条目
  - `其他/*.md` —— 其他文章
  - `images/` —— 图片资源
- 工程文件（一般无需改动）：
  - `.vitepress/config.mts` —— 站点配置（导航、侧边栏自动生成、搜索、rewrites）
  - `.vitepress/theme/` —— 主题与品牌配色
  - `package.json` —— 依赖与脚本
  - `.github/workflows/deploy.yml` —— GitHub Pages 自动部署

## 二、本地预览

环境要求：Node.js 20 及以上（开发环境使用 22，CI 使用 24）。

```powershell
npm install           # 首次运行，安装依赖
npm run docs:dev      # 开发模式，改文件即时生效
                      # 打开 http://localhost:5173/MDY-wiki/

npm run docs:build    # 构建正式产物（输出到 .vitepress/dist）
npm run docs:preview  # 本地预览正式产物 http://localhost:4173/MDY-wiki/
```

提示：

- 修改 `.vitepress/config.mts` 后开发服务器会自动重启。
- 若页面全白，先在终端或浏览器控制台查看报错。
- 重新构建后如果 `docs:preview` 出现 404 或旧内容，重启 `docs:preview` 即可（预览服务器启动时会缓存一次文件列表）。

## 三、投稿 / 新增条目

1. 个人线：在 `个人线/` 下新建 `<名字>/main.md`（可参考 `模板/` 目录下的模板文件）。
2. 队伍线：在 `队伍线/` 下新建 `<队伍名>/main.md`。
3. 其他文章：直接把 `.md` 文件放进 `其他/`。
4. 图片：放进 `images/`，正文中按现有条目的写法引用。

格式约定（详见站点内"投稿指南"页面）：

- 正文标题从 `##` 级开始写（页面标题由站点自动生成，无需手写一级标题）。
- 事件标头可用 `<font color="green">【事件名】-日期</font>` 的写法（与现有条目、贴吧一致）。
- 参考文献锚点 `<a name="ref-N">` 保持原样，站点会自动补充可跳转的 id。

新增条目后：

- 侧边栏会自动收集新条目（构建时扫描目录），重启 `docs:dev` 或重新构建后生效。
- 总目录 `目录.md` 等汇总页如需登记，请手动更新。

## 四、部署到 GitHub Pages

1. 一次性设置：仓库 Settings → Pages → Build and deployment → Source 选择 **GitHub Actions**。
2. 之后每次推送到 `main` 分支会自动触发部署（`.github/workflows/deploy.yml`）。
3. 部署进度在仓库 Actions 页面查看；完成后站点地址为：
   `https://givemeasmileqaq.github.io/MDY-wiki/`
4. 工作流会完整拉取 git 历史，用于每页"最后更新于"时间戳。

## 五、注意事项

- 提交前建议本地运行 `npm run docs:build` 确认无报错。
- 不要提交 `.vitepress/dist` 与 `.vitepress/cache`（已在 `.gitignore` 中忽略）。
- 站点 `base` 为 `/MDY-wiki/`，与仓库名一致；若仓库改名需同步修改 `.vitepress/config.mts` 中的 `base`。
